# UrbanPhotoMeshQA 人工质量评分操作指南

> 适用对象：香港城市摄影测量单体 glTF Mesh  
> 推荐方式：5档文件夹分类，拖动匿名评分条目  
> 重要原则：不移动原始数据，不查看攻击类型和预设强度，不使用Clean模型作对照

## 1. 需要给哪些数据评分

正式人工评分对象应以迭代2正式Manifest为唯一清单：

```text
artifacts/manifests/iteration2_quality_dataset_stage1_effective_seed2026.json
```

清单共`6289`个可独立打开的glTF样本：

| Split | 样本数 |
|---|---:|
| Train | 3903 |
| Val | 843 |
| Test | 825 |
| Blind | 718 |
| 合计 | 6289 |

这些样本包括340个Clean建筑，以及它们对应的真实文件级几何或纹理退化版本。人工评分时应混合、匿名、随机呈现四个Split，不让评分人看到Split、攻击类型、攻击强度或机器伪MOS。

本地外置硬盘上的源数据位置是：

```text
/Volumes/SANDISK-ELE/UrbanPhotoMeshQA-Data/
```

其中：

- `HK3D-Individualised-Iteration2-300/`：迭代2 Clean模型；
- `HK3D-Individualised-Attack-v2/`：当前本地已有的攻击模型，但主要对应较早的184栋数据；
- 迭代2新增建筑的攻击包目前以正式Manifest和GPU数据为准。开始全量人工评分前，应先将缺少的攻击资产同步到外置硬盘，并生成“本地可评分Manifest”。

因此，不要直接把整个`HK3D-Individualised-Attack-v2`当作最终评分全集，也不要评分`Feature-Cache/`、`Targets/`中的NPZ或机器真值。最终应只评分正式Manifest列出的`.gltf + .bin + textures`资产包。

## 2. 推荐的文件夹拖动方案

建议建立独立评分工作区：

```text
/Volumes/SANDISK-ELE/UrbanPhotoMeshQA-Data/Human-Rating-v1/
├── 00_待评分/
├── 01_很差_Bad/
├── 02_较差_Poor/
├── 03_一般_Fair/
├── 04_良好_Good/
├── 05_优秀_Excellent/
├── 98_不确定_Review/
├── 99_技术异常_Invalid/
├── private_mapping.csv
└── instructions.txt
```

`00_待评分`内每个条目使用随机匿名编号，例如：

```text
S000001/
├── preview.mp4
├── contact_sheet.jpg
└── asset → 原始glTF资产包的只读符号链接
```

实际拖动的是`S000001`这样的小评分条目，不是原始模型文件夹。这样有四个好处：

1. 不会破坏glTF、BIN和贴图的相对路径；
2. 不会改变正式Manifest；
3. 拖动很快，且不会复制大量数据；
4. 可通过`private_mapping.csv`将匿名编号还原到`asset_id/attack/level/split`。

`private_mapping.csv`在评分过程中不要打开，文件夹名也不得包含`light/medium/heavy`或攻击名称，避免主观评分被机器标签暗示。

## 3. 五档评分标准

评分问题统一为：

> 只看当前这个模型本身，如果它作为可交付的城市三维实景模型，其总体视觉质量属于哪一档？

| 档次 | 含义 | 判断标准 | 建议数值映射 |
|---|---|---|---:|
| 5 优秀 | 几乎无可察觉缺陷 | 轮廓、表面和贴图自然，可直接交付 | 1.00 |
| 4 良好 | 有轻微缺陷 | 仔细看能发现，但不明显影响使用 | 0.75 |
| 3 一般 | 缺陷清楚可见 | 质量下降明显，但主体仍完整可用 | 0.50 |
| 2 较差 | 严重缺陷 | 孔洞、变形、低清、缺失或错位明显影响使用 | 0.25 |
| 1 很差 | 基本不可接受 | 大面积损坏或强烈视觉错误，难以正常使用 | 0.00 |

评分必须依据“可见影响”，不能因为知道它可能属于某种攻击，就机械地按攻击参数分档。两个不同攻击即使参数档次相同，视觉质量也可以不同。

边界规则：

- 在相邻两档间犹豫时，先放入`98_不确定`，当日最后集中复核；
- 模型打不开、贴图依赖缺失、渲染全黑等技术故障放入`99_技术异常`，不把技术故障直接评为1分；
- 建筑本身造型简单不等于低质量；只评价重建/模型质量，不评价建筑设计美丑；
- 体量大、面数高、贴图分辨率高不自动等于高质量；
- 不与Clean原版并排比较，保持无参考评价协议。

## 4. 最快的实际操作流程

### 4.1 评分前准备

1. 插入并确认`/Volumes/SANDISK-ELE`已挂载。
2. 将评分工作区按随机顺序拆成若干批次，每批建议`100～200`个样本。
3. 每个样本预先生成相同相机、相同背景、相同光照的六视图转台视频或联系表。
4. 显示时默认先看`preview.mp4`；只有难以判断时才打开交互式glTF。
5. 显示窗口、屏幕亮度和观看距离尽量固定。

推荐单个样本操作：

```text
双击匿名条目
→ 看5～10秒转台视频
→ 必要时看六视图联系表或交互模型
→ 关闭预览
→ 将整个Sxxxxxx文件夹拖入1～5档之一
```

Finder建议使用“列表视图”，并把1～5档文件夹固定在侧边栏。也可以同时打开两个窗口：左侧`00_待评分`，右侧五个评分档次。

### 4.2 评分节奏

- 每次连续评分不超过`30～40`分钟；
- 每轮约`100～150`个样本后休息；
- 一天不建议超过`500`个，避免后半段标准漂移；
- 不要连续显示同一建筑的Clean、light、medium、heavy版本；
- 每批混合不同建筑、图幅和退化形式。

按每个样本平均`10～15秒`估算，全量6289条纯观看和拖动约需`18～26小时`，加上休息与复核，建议分`5～10天`完成。

## 5. 推荐先做Pilot，再做全量

为了尽快发现评分标准是否可操作，先做一个`300`条匿名Pilot：

- 六类退化均衡；
- light/medium/heavy均衡；
- 不同图幅和建筑均衡；
- 包含一定数量Clean；
- 不向评分人展示上述分组信息。

Pilot完成后检查：

- 五档是否都有足够样本；
- 是否大量样本进入`98_不确定`；
- 同一退化的视觉严重程度是否总体单调；
- 随机重复插入的20～30条样本，前后评分是否一致。

若重复样本大多相差不超过1档，即可按同一标准继续全量评分。不要根据模型预测结果修改人工分数。

## 6. Overall、Geometry和Texture如何标

最快且最重要的是先完成一遍`Overall Quality`五档评分。这一列可作为论文中的主要人工主观真值。

如果还要给模型的Geometry和Texture分支建立人工真值，建议不要在第一次观看时同时填写三个分数，以免速度太慢、维度混淆。采用三遍独立拖动：

```text
Pass 1：Overall总体质量
Pass 2：Geometry几何质量
Pass 3：Texture纹理质量
```

Geometry评分只看孔洞、表面噪声、尖刺、轮廓、拓扑破损和过度简化；Texture评分只看清晰度、区域缺失、错位、重影及材质完整性。第二、三遍可以先标有明显相关缺陷的样本，其余样本默认保持高档，但必须抽样复核。

建议最终保存三列：

```text
sample_code,overall_grade,geometry_grade,texture_grade,rater_id,rated_at,review_flag
```

## 7. 一个人评分与MOS的区别

一个人完成的结果严格来说是“主观评分”或`Opinion Score`，不是统计意义上可靠的MOS。MOS是多个评分人的分数平均值：

```text
MOS = 同一样本所有有效评分人的平均分
```

论文正式发布建议至少邀请`5`名有效评分人；条件允许时以`15～25`人为目标。所有人使用同一匿名工作区结构，但每个人的随机顺序应不同。最终先剔除明显不可靠评分人，再计算每个样本的平均分、标准差和置信区间。

如果现阶段只有你一人，可先完成Pilot或全量初标，用于验证标签体系和训练流程；论文定稿前再组织多人复评。你的评分不要和其他评分人的文件夹混合，每位评分人单独保存一个目录。

## 8. 从文件夹汇总为标签

评分结束后，程序应扫描`01～05`文件夹，以条目所在目录作为等级，再结合`private_mapping.csv`生成：

```text
human_ratings_rater01.csv
human_ratings_rater01.json
```

必须检查：

- 每个匿名编号只出现一次；
- `00_待评分`是否已经为空；
- `98_不确定`是否全部复核；
- `99_技术异常`是否有明确原因；
- 标签数量是否与本轮评分清单一致；
- 汇总文件记录评分协议版本和评分人匿名ID。

原始评分文件夹、映射表和汇总CSV都要保留，不要只留下最终数值，以便论文审计和复现。

## 9. 当前最推荐的执行顺序

```text
同步完整迭代2攻击资产到外置硬盘
→ 生成匿名评分工作区和统一预览
→ 你先完成300条Overall Pilot
→ 检查重复评分一致性和五档分布
→ 固定评分规则
→ 完成全量Overall评分
→ 组织其他评分人独立评分
→ 计算正式MOS
→ 再决定是否增加Geometry/Texture独立人工评分
```

在人工MOS完成前，现有Pseudo-MOS v3继续用于机器快速实验，但论文中的“人工主观质量”结果必须与机器伪MOS明确区分。
